# Rogers Mwenda — Version 2

An alternative GitHub Pages profile with a distinct finance-advisory visual direction: midnight navy, cobalt blue, restrained gold, sharp metrics and a more executive information hierarchy.

## Why this version leads with the bond transaction

The first version used premium-receipting efficiency as its main quantified achievement. This version puts the more strategic capital event first:

- **€40M corporate bond refinancing** — Rogers’ CV states that he contributed to the transaction.
- **2.5% lower financing costs** — the stated outcome associated with that transaction.
- **€425M+ asset base** — treasury and finance operations supported across a multi-entity group at that scale.
- **€185M+ revenue business** — liquidity activities managed for the insurance business.
- **≈90% matching efficiency** — a meaningful operational improvement, now positioned as supporting evidence for ERP-enabled process transformation.

The wording keeps attribution close to the evidence: “contributed,” “supported” and “managed.” It does not claim corporate restructuring. The strongest policy proof is contribution to liquidity, investment and foreign-exchange treasury policy reviews and governance.

## Positioning

The page is built to reach insurance-finance transformation consultancies and employers seeking interim, permanent or project support in:

- Accounting, financial control and reporting
- Controlling, FP&A and business partnering
- Treasury, liquidity, investment and financial risk
- ERP, process, governance and payment transformation
- Operational and commercial finance in adjacent industries
- ESG and sustainable-finance reporting, with circular-enterprise and green-SME access-to-finance learning

It makes regulated insurance finance the direct foundation, and describes manufacturing, food, retail and logistics as transferable operating contexts. Consulting and green-enterprise work are presented as growth directions rather than completed client assignments.

The text follows the CV wording found in the prior profile work. Update or remove any figure you would not want to explain in an interview.

## Upload to the existing GitHub Pages site

1. Extract `rogers-profile-v2.zip`.
2. Open the existing GitHub Pages repository.
3. Upload and replace `index.html`, `style.css`, `photos.css`, `script.js`, `favicon.svg` and `.nojekyll` in the publishing folder. Upload the `assets` folder too. For `main` and `/(root)`, use the repository root.
4. Commit the changes to the publishing branch. GitHub Pages will deploy the second design at the same site address.

Keep the current page files backed up if you want to switch between the two designs later.
